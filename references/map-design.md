# 图形化编程游戏地图设计规范

本规范适用于走迷宫、道路驾驶、寻路、巡游等依赖空间移动的关卡。用户指定地图风格或游戏规则时，优先遵循用户要求；无特别指定时按以下规则设计。地图美术、关卡规则和模拟器必须引用同一份拓扑数据，不能各自画一张看似相同但连接关系不同的地图。

## 1. 先选择空间模型和动作单位

实现地图前，明确采用哪种模型，并在界面/规则中说明其单位：

- **离散格网**：地图有可见、等尺寸的格子。定义每格的实际/逻辑尺寸、坐标、朝向以及前进一格的含义。只有在模型确实有格子时，才使用“前进一步/一格”。
- **显式路网**：地图由节点和边组成。为每条边定义端点、长度、方向和允许的速度/通行规则。若一条边代表一段有长度的道路，移动距离仍由速度和时间决定；只有教学目标明确是节点图遍历时，才可把“到相邻节点”定义为一个离散操作，并在图例中说明。
- **连续空间**：地图没有格子时，定义坐标单位、世界边界、起点、方向角和物体尺寸。移动积木必须包含明确时长，并使用当前速度计算位移。默认恒速模型下，`距离 = 速度 × 时间`，因此“前进 t 秒”按当前速度计算位移；禁止未定义的“前进一步/前进一站”，也不允许仅按目标点瞬移。

速度、距离、时间必须使用明确且兼容的单位；如速度用 km/h、时间用秒，需显式换算到地图距离单位。若游戏采用加速度、转弯半径或简化动画时间，分别说明公式和模拟时间比例，不得让动画播放时长冒充物理时间。

连续移动时，按小时间步或解析碰撞确定运动轨迹。遇到墙、边界或危险时，在首次接触点停止/触发既定结果，不得穿透后再把角色瞬移回来。转弯动作也要量化：使用角度，或明确转向输入与持续时间/转弯半径的关系。

## 2. 先定义拓扑，再绘图

在绘制地图前，定义可通行的网格或道路图：

- 记录起点、终点、坐标/节点、可通行连接、墙/不可达区域、危险格、路口、检查点、信号灯等实际会影响程序的对象。
- 对格网地图，明确格子坐标、格子尺寸、角色朝向和邻接规则；对显式路网，明确节点、边、边长和方向；对连续地图，明确世界坐标及可通行/碰撞几何。不得靠 SVG 路径或 CSS 装饰线推断可走关系。
- 地图绘制和模拟移动必须消费同一份权威邻接数据。若地图用显式 `edges`，移动也必须查询这些边；若用规则网格推导邻接，则渲染必须显示所有可移动的相邻连接。不能一边按线段/边列表绘图，另一边仅按坐标距离推断可走。
- 只有离散格网可以把“前进一步”定义为前进一个格。连续空间必须使用明确时长的动作，且位移按当前速度与时长计算；不得让一个移动指令直接跳到列表中的下一站或沿预设线路自动转弯。
- 地图上的障碍、陷阱、红绿灯、站点和目标必须绑定到拓扑节点/边，并真实影响执行状态和结果。纯装饰元素不应看起来像可交互危险或通路。

## 3. 地图必须服务学习目标

- 若教学目标包含前进、转向和路线规划，默认关卡地图至少应有两次方向改变和一个有意义的路线选择点；可通过障碍、不同长度/风险的通路或有教学目的的死路形成决策。不要用一条直线串起全部目标点。
- 仅在主路线旁添加不连通、不可进入或没有后果的短支线，不算有效分支。路线规划关卡至少有一个路口，其不同可行方向会通往不同的连通路径/目标，或产生明确且可观察的教学结果；单条必经链加装饰性岔口不算路径选择。
- 如果关卡只教顺序执行，或用户明确要求线性路线，可以采用简单路线，但仍须如实说明这是教学选择，不能声称在训练转向/寻路。
- 分支必须是真实可达的连接选择，不是画出的岔路实际仍被代码强制传送回固定路线。危险/信号灯可以按学习目标逐关引入，不为增加视觉复杂度而塞入无关障碍。
- 对多个目标点/企业站点，使用弯折或有支路的连通路网安排点位；若要求按顺序讲解，程序仍需逐段移动并可观察经过的路线，不能凭“下一站”积木瞬间跳点。
- 用图形化编程教学时，关卡挑战必须允许学生实际组装并运行与本关概念对应的积木；多选题可作为辅助手段，不能代替程序挑战。
- 难度通过格数、岔路数、障碍布局、条件要求和路线效率逐步提高；地图形状本身不能制造不可见或不可解的谜题。

## 4. 地图视觉、贴图和资源约定

- 清楚区分起点、终点、可走区域、墙/边界、路口、危险、信号灯、目标点和角色当前位置；提供图例或就地标签，避免仅靠颜色编码。
- 可走通路须连续可追踪；相邻关系与路口几何视觉一致。转弯、死路和交叉口需能一眼区分，路线或路径高亮不得遮挡障碍与目标。
- 角色的位置和朝向都应可见；格网中的移动依赖当前朝向，连续空间中的位移依赖当前朝向、速度和指令时长。执行动画结束后角色必须落在模拟状态对应的位置。
- 先定义地图图层：底色/地形、道路/可走区、标线/格线、障碍/机关、目标/站点、角色/车辆、路径高亮和 UI 标签。各层顺序、遮挡规则和交互层必须稳定；纯装饰纹理不可改变可走性。
- 同类地图资产统一视角（俯视、等距或侧视择一）、透视、比例、光源方向、阴影软硬、描边、色板和细节密度。不得把不同视角或不同比例的图标直接拼在同一地图中。
- 格网地图的地块贴图须和格子尺寸对齐，边界/墙体无缝衔接；连续地图的道路贴图应沿路径连续铺设，转角、路口和边缘使用对应的衔接素材，不得拉伸单张纹理来掩盖几何断点。
- 角色/车辆的可视尺寸、旋转中心和碰撞体与地图单位一致；车辆朝向、阴影和贴图朝向必须与状态模型一致。碰撞边界由独立几何定义并与贴图可视边缘校准，不能从纹理颜色临时猜测。
- 小屏幕上地图可缩放或平移；缩放不得改变世界坐标、碰撞判定或格子判定。无格网地图不得通过贴图暗示存在实际格线。

## 5. 连通性、物理量和贴图校验

- 在关卡交付前，从地图数据运行可达性检查，确认起点能到达所有必需目标，并确认终点/顺序约束有可行解。
- 为教学意图列出至少一条参考路线。格网/路网记录格坐标或节点、每步朝向；连续空间记录坐标、速度、指令时长和预期位移。用实际原子积木模拟执行，确认它确实可通关。
- 对要求学生选择路线的关卡，验证至少存在一个真实分支和一个有意义的错误选择/死路；若有多个有效路径，不应只接受唯一节点序列。
- 遍历地图上每条绘制连接和每个可执行移动边，确认二者完全一致；尝试从分支向前移动、转弯和返回，确保没有只在画面出现或只在代码存在的道路。
- 对连续运动验证至少一个 `v × t` 位移例子、单位换算、转弯量化、碰撞停止位置和地图边界；对格网运动验证格子尺寸与前进单位相符。
- 检查贴图接缝、比例、角色朝向、碰撞体与可见资产边界；确认装饰纹理不会伪装成道路、墙或危险。
- 分别验证撞墙、进入陷阱、遇红灯未等待、到达终点、过早停止和重复前进等相关结果；地图显示、转移表和执行器结果必须一致。
